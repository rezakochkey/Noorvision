# Noorvision Roadmap

## Phase 0 — Foundation

- [x] Repository connected
- [x] Initial scaffold
- [x] Development branch created
- [x] Security-oriented `.gitignore`
- [x] Project manifesto

## Phase 1 — Definition

- [ ] Define the first concrete user problem
- [ ] Define the smallest useful product
- [ ] Choose the initial technology stack
- [ ] Define acceptance criteria

## Phase 2 — Prototype

- [ ] Implement the smallest end-to-end capability
- [ ] Add automated tests
- [ ] Document setup and usage

## Phase 3 — Reliability

- [ ] Add CI checks
- [ ] Add linting and formatting
- [ ] Add dependency and security checks
- [ ] Establish release/versioning rules

## Phase 4 — Growth

- [ ] Deploy a useful first release
- [ ] Measure real usage
- [ ] Iterate based on evidence

The roadmap is deliberately conservative: capability is added when there is a demonstrated need rather than for its own sake.
