# Contributing to Noorvision

Noorvision is built incrementally. Contributions should keep the project understandable, testable, and easy to review.

## Workflow

1. Start from an up-to-date `main`.
2. Create a focused feature or fix branch.
3. Keep each change small enough to explain clearly.
4. Add or update tests when behavior changes.
5. Update documentation when a decision or public behavior changes.
6. Open a pull request with a concise description of the problem and solution.
7. Address review feedback before merging.

## Commit guidance

Use clear, action-oriented commit messages. Avoid mixing unrelated changes in one commit.

## Pull requests

A good pull request should explain:

- What changed
- Why it changed
- How it was tested
- Any known limitations or follow-up work

Do not include secrets or sensitive personal information in commits, issues, or pull requests.
